# 设计规范：内容关联及其侧边栏精简显示优化

## 1. 背景与目标
随着用户标记数量的增加，侧边栏出现了“滚动地狱”和信息过载问题。目前按网页平铺的方式无法体现用户在进行特定课题研究时的内容关联。

目标是引入 **“标签/课题 (Topic)”** 维度，通过自动聚类和三级树状结构，实现内容的有机归纳和精简展示。

## 2. 核心概念
- **标签 (Tag)**：跨网页的内容分类标识。支持手动创建和算法自动生成。
- **收集箱 (Inbox)**：默认容器，存放尚未归类或未达到聚类阈值的零散标记。
- **虚拟文件夹**：侧边栏的展示逻辑，支持一个标记在多个标签文件夹下重复出现（多对多关联）。

## 3. 技术设计

### 3.1 数据模型扩展

#### `Mark` 接口更新 (`src/logic/storage.ts`)
```typescript
export interface Mark {
  // ... 现有字段 ...
  tags: string[]; // 关联的标签 ID 列表
}
```

#### 新增 `Tag` 接口
```typescript
export interface Tag {
  id: string;
  name: string;
  color: string;
  isAutoGenerated: boolean;
  createdAt: number;
  updatedAt: number;
}
```

### 3.2 自动聚类算法 (Automatic Clustering)

#### 触发时机
每当创建新标记或编辑标记内容时触发。

#### 聚类逻辑 (Threshold-based Promotion)
1. **特征提取**：提取当前网页的 `Title`、`Meta Keywords`、`Meta Description` 以及标记文本。
2. **关键词共现分析**：
   - 维护一个内存中的临时词频统计。
   - **晋升阈值**：当同一个关键词在 **>= 2 个不同域名** 的网页中出现，且相关标记数量 **>= 3** 时。
3. **标签生成**：
   - 达到阈值后，系统在“收集箱”顶部建议创建新标签。
   - 用户确认后，相关标记自动从收集箱转移到新标签空间。

### 3.3 侧边栏 UI 架构

#### 三级树状结构
1. **Level 1: 文件夹层 (Tags/Inbox)**
   - 默认置顶：`收集箱 (Inbox)`。
   - 下方排列：用户创建或确认的标签文件夹。
2. **Level 2: 网页层 (Pages)**
   - 展开文件夹后，显示该标签下的所有网页标题。
   - 按网页内最新标记的时间倒序排列。
3. **Level 3: 标记层 (Marks)**
   - 展开网页后，显示具体的划线内容和备注。

#### 交互细节
- **多对多展示**：如果标记有多个标签，它会出现在每个对应文件夹下。
- **Tooltip 集成**：在划线后的浮动工具栏中，显示已关联的标签芯片，并提供自动发现的建议标签供点击。

## 4. 存储策略
- 使用 `chrome.storage.local` 存储标签元数据 `tags-meta-storage`。
- 修改 `marks-by-url-storage` 以持久化每个 Mark 的 `tags` 数组。

## 5. 验证计划

### 5.1 逻辑验证
- 验证算法能否正确识别跨域名的相同关键词。
- 验证“多对多”关联下，修改一个位置的笔记，其他位置同步更新。

### 5.2 UI 验证
- 验证收集箱与标签文件夹的切换逻辑。
- 验证在标签文件夹下删除标记时，是“取消关联”还是“彻底删除”的交互（默认应为取消关联，除非是收集箱）。
