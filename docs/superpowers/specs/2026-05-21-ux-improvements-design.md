# 设计规约：侧边栏交互优化与 Markdown 导出降级

- **状态**：待评审
- **日期**：2026-05-21
- **关联 Issue**：[#39](https://github.com/catx1726/MarkFlow/issues/39), [#38](https://github.com/catx1726/MarkFlow/issues/38)

## 1. 目标 (Goals)

针对用户在管理大量标记时的“滚动地狱”痛点，以及导出内容难以嵌入已有文档的兼容性问题，进行针对性交互与功能优化。

1.  **侧边栏互斥折叠**：实现手风琴交互，减少视觉负载。
2.  **视觉辅助**：通过徽章直观反馈标记数量，通过置灰提示空分类。
3.  **Markdown 格式降级**：将导出内容从“独立文档格式”转变为“可嵌入片段格式”。

## 2. 方案详述 (Detailed Design)

### 2.1 互斥手风琴交互 (#39)

我们将放弃复杂的 JavaScript 状态管理，采用现代浏览器的原生能力。

-   **核心组件**：使用 `<details>` 标签包裹每个标签文件夹。
-   **互斥逻辑**：为所有标签文件夹的 `<details>` 标签设置相同的 `name="tag-folder"` 属性（需 Chrome 120+）。
-   **默认状态**：
    -   `inbox` (收集箱)：设置 `open` 属性。
    -   其他标签：默认折叠。
-   **徽章逻辑**：
    -   定义计算属性或在 `TagTree` 中预存 `totalMarks`。
    -   公式：`totalMarks = sum(page.marks.length for page in pages)`。
-   **样式增强**：
    -   当 `totalMarks === 0` 时，为整个 `<summary>` 区域添加 `opacity-50` 类名，降低视觉优先级。

### 2.2 Markdown 导出结构重构 (#38)

重构 `exportToMarkdown` (单页导出) 和 `exportTagFolder` (整标签导出) 函数中的模板字符串。

#### 2.2.1 单页导出模板
-   **来源声明**：将 `# [页面标题](URL)` 替换为 `> 来源：[页面标题](URL)`。
-   **分组标题**：将 `## 分组名` 替换为 `**分组名**`。
-   **内容引用**：保持 `> 标记内容`。
-   **分隔符**：统一使用 `---`。

#### 2.2.2 整标签导出模板
-   **标签标题**：将 `# 标签名` 替换为 `**标签名**`。
-   **页面标题**：将 `## [页面标题](URL)` 替换为 `**[页面标题](URL)**`。
-   **分组标题**：将 `### 分组名` 替换为 `**分组名**` 或 `*分组名*`。

## 3. 技术实现 (Technical Implementation)

### 3.1 关键代码改动

-   **`src/sidepanel/Sidepanel.vue`**:
    -   更新 `<template>` 中的文件夹渲染部分。
    -   修改 `exportToMarkdown` 函数逻辑。
    -   修改 `exportTagFolder` 函数逻辑。
-   **`src/logic/tagTree.ts`**:
    -   更新 `TagTree` 接口，在每个 `TagFolder` 中增加 `totalMarks: number` 字段，方便 UI 层直接读取。

### 3.2 兼容性与风险
-   **互斥属性兼容性**：`<details name="...">` 是较新特性，由于本项目是 Web 扩展且基于 Chrome/Edge 生态，兼容性符合要求。若用户浏览器版本过低，则退化为普通折叠（非互斥），不影响基本功能。
