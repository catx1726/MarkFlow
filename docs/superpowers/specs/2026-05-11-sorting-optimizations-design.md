# 设计规范：侧边栏排序优化 (#31 & #32)

## 📋 问题描述

目前侧边栏的实现存在两个主要的可用性问题：
1. **标记顺序问题 (#31)**：标记是按创建时间（或按标题分组）显示的。如果用户先标记了后面的段落，再标记前面的段落，侧边栏的显示顺序会与阅读顺序不符（显示为 B-A）。
2. **网页顺序问题 (#32)**：侧边栏中的网页顺序取决于第一个标记添加的时间。用户期望最近活跃（最近添加或编辑标记）的网页显示在最上方。

## 🎯 核心目标

- [ ] 确保页面/分组内的标记按其在文档中的物理位置排序。
- [ ] 确保侧边栏中的网页按活跃度（最新标记创建/编辑时间）排序。
- [ ] 保持对没有位置数据的旧标记的向下兼容。

## 🛠 技术方案

### 1. 数据模型更新
在 `src/logic/storage.ts` 的 `Mark` 接口中增加 `domIndex` 字段。该字段将存储标记在文档正文中的绝对字符偏移量。

### 2. 内容脚本实现
在 `src/contentScripts/ui.ts` 中创建新 `Mark` 时：
- 使用 `DOMScanner.calculatePreciseOffset(rangyRange, document.body)` 获取 `domIndex`。
- 将此值存储在 `Mark` 对象中。

### 3. 侧边栏排序逻辑
更新 `src/sidepanel/Sidepanel.vue` 中的 `structuredMarks` 计算属性：
- **网页排序**：按 `Math.max(...marks.map(m => m.createdAt))` 对 URL 进行排序。
- **标记排序**：按 `domIndex` 对组内标记进行排序。如果 `domIndex` 缺失或相同，则回退到 `createdAt`。

## ✅ 验收标准

- [ ] 以相反顺序添加的标记（先页面末尾后页面开头）在侧边栏中按正确的阅读顺序显示。
- [ ] 新更新的页面（添加了新标记）移动到侧边栏列表的顶部。
- [ ] 现有标记（无 `domIndex`）仍能正确显示，并按创建时间排序。

## 📝 补充说明
恢复机制保持不变，仍依赖于 `rangySerialized`。`domIndex` 严格仅作为 UI 排序提示。
