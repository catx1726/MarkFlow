# 棘手问题归档指南 (Debugging Recipes)

## 目的

记录那些“表象简单、根因隐蔽”的问题，帮助团队共同成长，避免重复踩坑。每次解决完一个棘手问题后，应将其归档到本目录下。

## 什么算“棘手”

满足以下任一条件即可归档：

- 花 ≥2 轮才定位或修复
- 涉及跨组件、跨 context、跨进程的隐式行为
- 根因和表象不一致（例如报错位置不是真正出错位置）
- 调试过程中使用了值得复用的技巧或工具
- 未来很可能以不同形式再次出现
- 修复方案包含非显而易见的权衡或规避手段

## 归档格式

每个案例使用以下结构：

```markdown
# <简短标题>

## 现象 (Symptom)

## 根因 (Root Cause)

## 调试路径 (Debugging Trail)

## 修复方案 (Fix)

## 经验教训 (Lessons)

## 关联代码

## 关联 Issue/PR
```

详见模板库 `docs/playbooks/README.md`。
