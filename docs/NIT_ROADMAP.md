# MarkFlow 后续迭代建议 (基于 AI CR NIT 项目分析)

本文档总结了 PR #37 (内容关联与标签系统) 和 PR #41 (GitHub Gist 同步) 中 AI 提出的轻微建议 (NIT)，并对其修改价值进行了深度评估，作为后续迭代的 Roadmap 参考。

---

## 1. 架构与性能类 (High Value)

| 建议项目 | 来源 | 成本 | 收益 | 推荐等级 | 评估理由 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Sidepanel 逻辑拆分 (Composables)** | PR #37 | 中 | 高 | ⭐⭐⭐⭐⭐ | 目前 `Sidepanel.vue` 脚本体积过大。拆分为 `useTagManagement`, `useMarkActions` 等可极大提升可维护性。 |
| **i18n 国际化支持** | PR #41 | 中 | 中 | ⭐⭐⭐⭐ | 错误消息目前是硬编码中文。作为浏览器扩展，支持国际化是走向社区的基础，且现在开始做成本最低。 |
| **Gist 字符串常量化** | PR #41 | 低 | 低 | ⭐⭐⭐ | `'markflow_sync.json'` 等字符串多次出现，提取常量可减少 typo 风险。 |
| **统一消息返回格式** | PR #37 | 中 | 中 | ⭐⭐⭐⭐ | 目前部分消息返回 `newTag`，部分返回 `{success, error}`。统一格式可简化前端的错误处理模板代码。 |

## 2. UI/UX 体验类 (Medium Value)

| 建议项目 | 来源 | 成本 | 收益 | 推荐等级 | :--- |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Tooltip 缓存标签列表** | PR #37 | 中 | 中 | ⭐⭐⭐ | 每次显示 Tooltip 都拉取全量标签。改用缓存 + 后台广播刷新，可消除打开时的微小延迟。 |
| **同步状态指示器增强** | PR #41 | 低 | 中 | ⭐⭐⭐⭐ | 增加“同步中...”动画或更详细的状态反馈，能有效缓解网络慢时的用户焦虑。 |
| **统一 Z-Index 管理** | PR #37 | 中 | 低 | ⭐⭐ | 针对 Sidepanel 内各种弹出菜单的硬编码 z-index。目前冲突概率低，但长期看是隐患。 |
| **Markdown 导出逻辑去重** | PR #37 | 低 | 中 | ⭐⭐⭐ | 侧边栏多处导出逻辑重复。提取通用函数符合 DRY 原则，降低后续修改导出的风险。 |

## 3. 工程化与代码质量 (Good to Have)

| 建议项目 | 来源 | 成本 | 收益 | 推荐等级 | 评估理由 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **增加 `buildTagTree` 单元测试** | PR #37 | 中 | 高 | ⭐⭐⭐⭐ | 这是侧边栏展示的核心逻辑，逻辑较复杂，增加测试能防止后续优化导致的树结构坍塌。 |
| **类型安全增强 (Protocol Types)** | PR #37 | 中 | 中 | ⭐⭐⭐ | 为所有消息定义明确的 Payload 接口，而不是使用 `any` 或弱断言。 |
| **清理不必要的 `toRaw`** | PR #37 | 低 | 低 | ⭐ | `webext-bridge` 传输本身会序列化，`toRaw` 确实冗余但不影响功能。 |
| **日志记录器 (Logger) 封装** | PR #41 | 中 | 中 | ⭐⭐⭐ | 统一管理 `console.log`，支持生产环境自动静默，比手动删除更科学。 |

---

## 4. 暂不执行 (Wontfix/Later)

- **GitHub API Rate Limit 监控** (PR #41): 目前 Gist 读写频率极低（10s 防抖），5000次/小时的配额几乎不可能触发，监控成本大于收益。
- **自动聚类算法增强 (TF-IDF)** (PR #37): 属于重量级特性。在用户量和数据量达到一定规模前，手动标签已足够，且此类算法在端侧执行性能压力大。
